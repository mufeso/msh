# Command reference

Generated by cmd/msh-docs from the program itself. Run `msh COMMAND --help` for the flags.

## msh c

```text
Usage: msh c TASK SERVER [ARG]... [flags]

Short form of: msh task run TASK --host SERVER --arg ARG...
```

## msh completion

```text
Usage: msh completion bash|zsh

Prints a shell completion script. Load it with:

  source <(msh completion bash)     # in ~/.bashrc
  source <(msh completion zsh)      # in ~/.zshrc, after compinit
```

## msh config

```text
Usage: msh config <subcommand> [flags]

Subcommands:
  init      Write a starter configuration and inventory
  show      Show effective settings and where each value came from
  validate  Validate the configuration and the inventory

Precedence: flag > environment variable > configuration file > default.
```

## msh config init

```text
Usage: msh config init [--dir DIR] [--force]

Writes a starter config.yaml and inventory.yaml (mode 0600) into DIR,
by default ~/.config/msh. Existing files are never overwritten unless
--force is given.
```

## msh config show

```text
Usage: msh config show [flags]

Shows every effective setting, its value and its source.
```

## msh config validate

```text
Usage: msh config validate [flags]

Loads the configuration file and the inventory, validates both, and
prints a summary. Exits 0 when everything is valid, 3 when the
configuration or inventory is invalid, and 8 when a file cannot be read.
```

## msh connect

```text
Usage: msh [flags] [user@]host[:port] [command...]
       msh [flags] --host LIST [[user@]host [command...]]
       msh [flags] --group NAME|--tag K=V|--all [command...]
       msh connect [flags] [user@]host[:port] [command...]

Connects like ssh. Without a command it opens a shell. With one it runs the
command on the server, with raw output and the remote exit status. The
server does not need to be in the inventory; if it is, its settings apply.
If it is not, ~/.ssh/config is used as ssh would. Host keys are always
verified.

--host adds more servers to the destination: a,b or "a b" or @FILE. The
first word after the flags is always a destination. --group, --tag and --all
take no destination: every word is the command. With several servers a
command runs on all of them in parallel, and without a command each server
opens in its own tmux pane.

Login uses keys from ssh-add first, then key files, then a password: the
MSH_PASSWORD environment variable, or a prompt on the terminal.

Examples:
  msh ops@server1
  msh root@server1:2222
  msh web01 df -h
  msh -t web01 top
  msh -p 2222 -l root -i ~/.ssh/key -J jump@bastion.example.com server1
  msh --host "web01 web02" root@db01 uptime
  msh --host web01,web02 root@db01 uptime
  msh --host @servers.txt root@db01 df -h
  msh --host web01,web02
  msh --group web uptime
```

## msh exec

```text
Usage: msh exec ([user@]host | --host LIST | --group NAME | --tag K=V | --all) --command CMD [flags]
       msh exec --local --command CMD [flags]

Runs a command line on a server over SSH, like "ssh user@server CMD".
The command is interpreted by the remote user's shell. It runs on every
selected server.

With --local the command runs on this machine with /bin/sh -c instead.
```

## msh history

```text
Usage: msh history <subcommand> [flags]

Subcommands:
  list    List recorded runs
  show    Show one recorded run
  diff    Compare two recorded runs
  prune   Remove old runs

msh records runs in ~/.local/state/msh/history. See docs/history.md.
```

```text
Usage: msh history list [--limit N] [flags]

Lists recorded runs, newest first.
```

## msh history show

```text
Usage: msh history show REF [flags]

Shows a recorded run. REF is "last", an ID, or a unique part of the start
of an ID.
```

## msh history diff

```text
Usage: msh history diff REF1 REF2 [flags]

Compares two recorded runs server by server. Exits 1 if they differ.
```

## msh history prune

```text
Usage: msh history prune --keep N

Removes all but the newest N recorded runs.
```

## msh logs

```text
Usage: msh logs ([user@]host | --host LIST | --group NAME | --tag K=V | --all) --file PATH [--lines N] [--follow] [flags]

Shows the last lines of a log file on each selected server (tail -n N).
With --follow, new lines are streamed live, prefixed with the server
name, until you press CTRL+C. Paths must be absolute and inside one of
the allowed_log_paths directories (default /var/log).
```

## msh packages

```text
Usage: msh packages <subcommand> [flags]

Subcommands:
  list    List installed packages
  check   Check that packages are installed
  find    Find packages across servers
  compare Compare servers with a baseline server
  updates List pending updates

Works on servers with rpm or dpkg. msh only reads package data here.
```

## msh packages list

```text
Usage: msh packages list [PATTERN] ([user@]host | --host LIST | --group NAME | --tag K=V | --all) [flags]

Lists installed packages. PATTERN works like grep: a name only has to contain
it, and it is a regular expression. It can also be given with --filter. The
first plain word is the pattern, so write user@host, or use --host, for the
server.

Examples:
  msh packages list tmux root@db01
  msh packages list '^kernel' --group web
  msh packages list ssl --ignore-case --all
```

## msh packages check

```text
Usage: msh packages check [REQ...] (user@host | --host LIST | --group NAME | --tag K=V | --all) [--package REQ[,REQ...] | --file FILE] [flags]

Checks requirements on each server and exits 1 if one is not met.
A requirement is NAME, NAME>=VERSION (also =, !=, <, <=, >) or !NAME, which
means the package must not be installed. Quote requirements in the shell.
```

## msh packages find

```text
Usage: msh packages find PATTERN ([user@]host | --host LIST | --group NAME | --tag K=V | --all) [flags]

Finds packages by name across servers and groups them by version.
PATTERN works like grep: a name only has to contain it, and it is a regular
expression: ssl, '^open', 'ssl$'.
```

## msh packages compare

```text
Usage: msh packages compare [PATTERN] (--group NAME | --all | ...) [--baseline SERVER] [flags]

Compares the installed packages of each server with a baseline server
(default: the first selected). Exits 1 when servers differ. PATTERN limits it
to matching package names and works like grep.
```

## msh packages updates

```text
Usage: msh packages updates [PATTERN] ([user@]host | --host LIST | --group NAME | --tag K=V | --all) [flags]

Lists pending updates (dnf, yum or apt). Nothing is installed. apt shows
what its last "apt update" found.
```

## msh script

```text
Usage: msh script run ([user@]host | --host LIST | --group NAME | --tag K=V | --all) --file PATH [--interpreter NAME] [--arg VALUE]... [flags]

Streams a local script to an interpreter on each selected server through
SSH standard input ("bash -s --", "sh -s --", "python3 -", "perl -").
The script is never copied to the server's disk. Supported interpreters:
sh, bash, python3, perl. Without --interpreter the script's shebang line
decides, else sh.
```

## msh shell

```text
Usage: msh shell --host NAME [--command CMD] [flags]
       msh shell (--group NAME | --all | ...) --tmux [flags]

Opens an interactive login shell on one server, like "ssh user@server",
or runs CMD there with a terminal, like "ssh -t user@server CMD".
msh exits with the remote exit status.

Example:
  msh shell --host server01 --command "podman exec -it asdf /bin/bash"
```

## Shortcuts

```text
Built-in shortcuts. Each runs one read-only remote command and accepts
the same selection, output and timeout flags as "msh exec".

  ping          Check SSH connectivity and authentication
                $ true
  uname         Show system information (uname -a)
                $ uname -a
  kernel        Show the kernel release (uname -r)
                $ uname -r
  uptime        Show uptime and load averages
                $ uptime
  disk          Show filesystem usage (df -hP)
                $ df -hP
  memory        Show memory usage in MiB (free -m)
                $ free -m
  services      List running systemd services
                $ systemctl list-units --type=service --state=running --no-pager --no-legend
  failed-units  List failed systemd units
                $ systemctl --failed --no-pager --no-legend
  selinux       Show the SELinux mode (getenforce)
                $ if command -v getenforce >/dev/null 2>&1; then getenforce; else echo 'SELinux tools are not installed'; fi
```

## Exit codes

| Code | Name | Meaning |
|-----:|------|---------|
| 0 | ok | every selected server succeeded |
| 1 | failure | a remote command ran and exited non-zero |
| 2 | usage | invalid command-line input |
| 3 | config | invalid configuration, inventory, task or task arguments |
| 4 | connection | DNS, TCP, SSH handshake, authentication, host key or bastion failure |
| 5 | timeout | a connection, command or the global timeout expired |
| 6 | transfer | a script could not be transferred |
| 7 | tmux | tmux is unavailable or failed |
| 8 | io | a local file could not be read or written |
| 70 | internal | an unexpected internal error (a bug in msh) |
| 130 | canceled | interrupted by CTRL+C, SIGTERM or SIGHUP |
